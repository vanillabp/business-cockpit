# The interview

*Part of the description in [`../SKILL.md`](../SKILL.md).*

Ask these questions before you generate anything. Ask every one of them. Where a default is given,
propose it, and let the user decide. Write every answer into `INTERVIEW.md` in the generated
project, with the question id.

Each question has an id, for example `Q-FOLLOW-UP`. The checklist
[reference-1.0.0.md](reference-1.0.0.md) names these ids, so you can see which items depend on
which answer. Ids are never reused.

## The stack

|          Id           |                                                                                                             Question                                                                                                             |  Default the agent proposes  |
|-----------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|------------------------------|
| `Q-FRAMEWORK`         | Which UI framework does the cockpit use, and which version?                                                                                                                                                                      | none, the user has to say    |
| `Q-DESIGN-LIBRARY`    | Which component or design library, and which version? For example PrimeNG, PrimeVue, MUI, Tailwind.                                                                                                                              | none, the user has to say    |
| `Q-MODULE-FRAMEWORKS` | Which frameworks, and which versions, do the workflow modules use for their forms and pages? Each module may pick its own, apart from the cockpit; an Angular module runs zoneless. This decides which dev shells are generated. | the same as `Q-FRAMEWORK`    |
| `Q-BUNDLER`           | Which build tool builds the cockpit? It does not matter for loading the modules, because the cockpit loads their parts with plain `import()`.                                                                                    | the default of the framework |

## The look and the words

|        Id        |                                                                                                                                Question                                                                                                                                 |       Default the agent proposes       |
|------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|----------------------------------------|
| `Q-THEME`        | Colours, fonts, logo, spacing. Also the colours of a row that is new, changed or removed while the user watches, and the one colour of an inactive row. They also go into the dev shell base pages.                                                                     | the defaults of the design library     |
| `Q-THEME-TOKENS` | Shall the theme be handed to module parts as CSS custom properties, so a form can look like the cockpit inside its shadow DOM?                                                                                                                                          | yes                                    |
| `Q-WORDING`      | Which word does the user interface use for a business case? In English `Case` or `Workflow`, in German `Vorgang` or `Fall`. Pick one per language and never mix. Use the word from `Q-WORDING` in every text of the generated user interface: the toggle in the
header, the list, the page, the messages, the menu. This description says "case" throughout.

First explain the follow-up (in German `Wiedervorlage`): a user can put a task aside until a date, its follow-up date. Until then the task is hidden from the default list. ## A user task and a case

|             Id              |                                                                                                                                                                                                                                                                                         Question                                                                                                                                                                                                                                                                                          |                                                                     Default the agent proposes                                                                     |
|-----------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `Q-HEADER`                  | What does the application header show in the views where no user task is open?                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            | the title, the toggle of the lists, the user and the menu                                                                                                          |
| `Q-TASK-PAGE-AREAS`         | Which areas does the cockpit lay out on the page of a user task? The convention is `body`, `information` (top of a column on the right) and `actions` (bottom of that column). The old cockpit had no areas, and every customer has asked for them. The answer may also be none: then the cockpit shows only the one web component of the area `all`, which every cockpit knows. A module may always return one web component instead and use the whole page, and a cockpit ignores areas it does not know, see [module-loading.md](module-loading.md#the-page-of-a-user-task-or-a-case). | `body`, `information`, `actions`; the user may choose none                                                                                                         |
| `Q-WORKFLOW-PAGE-AREAS`     | Which areas does the cockpit lay out on the page of a case? The convention is `body`, `information` (top of a column on the right) and `actions` (bottom of that column). The old cockpit had no areas, and every customer has asked for them. The answer may also be none: then the cockpit shows only the one web component of the area `all`, which every cockpit knows. A module may always return one web component instead and use the whole page, and a cockpit ignores areas it does not know, see [module-loading.md](module-loading.md#the-page-of-a-user-task-or-a-case).      | `body`, `information`, `actions`; the user may choose none                                                                                                         |
| `Q-TASK-INFORMATION-AREA`   | Ask only when `Q-TASK-PAGE-AREAS` has the area `information`. Which information about the task do the workflow modules show themselves in the area `information`? The application header then does not show it again (`Q-TASK-HEADER-INFO`). This is a convention between the cockpit and its workflow modules, like the areas.                                                                                                                                                                                                                                                           | business id, case title                                                                                                                                            |
| `Q-TASK-HEADER-INFO`        | Which information about the open user task does the application header show? For example task kind or case kind. It never needs the task title, because the form shows it. It also leaves out what the modules show in the area `information` (`Q-TASK-INFORMATION-AREA`). So with the default answers the header shows little or nothing here.                                                                                                                                                                                                                                           | nothing when the page has the area `information` with the default of `Q-TASK-INFORMATION-AREA`; case title and business id when the page has no area `information` |
| `Q-TASK-HEADER-ACTIONS`     | Which actions on the open user task does the application header offer? For example claim, follow-up, note, mark as unread, list in its own window.                                                                                                                                                                                                                                                                                                                                                                                                                                        | claim, follow-up, note, mark as unread, list in its own window                                                                                                     |
| `Q-WORKFLOW-HEADER-INFO`    | Which information about the open case does the application header show? For example case kind. Never the case title and never the business id: the main area of the page of a case shows them. If the page of a case has several areas (`Q-WORKFLOW-PAGE-AREAS`), even less goes into the header.                                                                                                                                                                                                                                                                                         | nothing                                                                                                                                                            |
| `Q-WORKFLOW-HEADER-ACTIONS` | Which actions on the open case does the application header offer? For example note.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | note                                                                                                                                                               |
| `Q-OWN-WINDOW`              | Is there a button "list in its own window" in the header of an open user task? A task and a case always open inside the application, in the same tab. So the list moves out into a window of its own, and the form keeps its input. Outlook pops out a mail; here it is the other way round, because a form would lose its input in a new window. After that, the task tab keeps the application header, because it holds the task actions. Only the burger menu goes, and a red "back to the list" button takes its place.                                                               | yes                                                                                                                                                                |

Ask the two questions about the areas before the questions about the header. What the areas show
decides what the header still has to show.

An earlier draft asked one question, `Q-PAGE-AREAS`, for both pages. `Q-TASK-PAGE-AREAS` and
`Q-WORKFLOW-PAGE-AREAS` replace it, and its id stays taken.

## Extension points

|          Id          |                                                                                                                                                                                                                                                                                                                                                                            Question                                                                                                                                                                                                                                                                                                                                                                            |                                                          Default the agent proposes                                                          |
|----------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------|
| `Q-EXTENSION-POINTS` | Which extension points exist beyond the four minimum ones (the page of a user task, the page of a case, the columns of the task list, the columns of the case list)? An extension point gives modules a place for a function of their own. Ask about each of these, and about any other the organisation wants: `Header`, buttons of a module in the application header, which may open a modal dialog like a start form; every customer so far has had it. `Pages`, pages of a module with their own menu entries; no customer has had them so far, an example is a page to keep the master data a process needs. A cockpit ignores the entries it does not know, so a module with a `Header` still works in a cockpit without one, only without its buttons. | `Header`: yes. `Pages`: no                                                                                                                   |
| `Q-CELL-RENDERING`   | Shall workflow modules draw cells of a list themselves? This is an open question and not generated yet. Prompt `1500` works it out, and its result may relax the rule that nothing is shared, for cells only, see [module-loading.md](module-loading.md#cells-drawn-by-a-workflow-module).                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | no                                                                                                                                           |
| `Q-UI-URI-TYPE`      | Which values of `ui-uri-type` does this user interface understand? The type decides how a row opens. They are a convention between this user interface and its workflow modules. VanillaBP knows no names for them. The types library lists them, the module kit exports them again, and the types jar carries them as constants.                                                                                                                                                                                                                                                                                                                                                                                                                              | `ES_MODULES` for parts loaded as ES modules from the module's manifest, `EXTERNAL` for pages of a module's own, opened in a tab of their own |
| `Q-DATA-ENTRY-LIMIT` | How large may a data entry of a module be, together with every file it imports? A data entry, like the columns of a list or the function that picks the form of a user task, is plain JavaScript without a framework. The forms themselves are visual entries, and the limit does not hold for them. `bc-check-entries` of the module kit fails the module's build above this limit, see [module-loading.md](module-loading.md#data-entries-carry-no-framework).                                                                                                                                                                                                                                                                                               | 32 KB before compression                                                                                                                     |
