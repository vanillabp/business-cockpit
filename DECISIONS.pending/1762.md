# A list of workflows has the modes `InProgress` and `Done`, and keeps `Active` and `Inactive` as deprecated second names

This decision adds to decision 70 and leaves its part about user tasks as it is. Decision 70 names
`Active` as the mode a list of workflows gets without `mode`. That list is now called `InProgress`.
It is the same list. Whoever merges this entry adds a line to decision 70 which points here.

Decided on 2026-11-05 by the maintainer.

## What was found

`WorkflowRetrieveMode` had `All`, `Active` and `Inactive`. `Active` meant "has not ended", so a
suspended workflow was in it. Since the cockpit knows "suspend" and "activate", a reader takes
`Active` for "not suspended" and `Inactive` for "suspended". Both are wrong.

## What the cockpit does now

`WorkflowRetrieveMode` has `All`, `InProgress` and `Done`. `InProgress` shows the workflows which
have not ended, suspended ones included. `Done` shows the ended ones. Without `mode` a list gets
`InProgress`.

`Active` and `Inactive` stay in the OpenAPI file as deprecated second names. `Active` gives the same
list as `InProgress`, and `Inactive` the same as `Done`. They go with the next major version at the
earliest. The cockpit and the dev-shell simulator map them onto the new names, so nothing behind the
API knows them. `WorkflowlistService.RetrieveItemsMode` has only `All`, `InProgress` and `Done`.

## Why second names this time

Decision 70 removed `OpenTasks` without a second name, because the break was cheap before 1.0 and a
quiet rename would keep the old name anyway. Here the old names are not a duplicate which confuses
somebody. They are the names every user interface sends today, and they keep working while the
user interfaces move. The description of the schema says which name is the new one, so somebody who
builds a user interface sees no riddle.
