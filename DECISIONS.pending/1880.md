# A task which is not open any more answers 404, and 409 means that another user claimed it

Decided on 2026-11-17 by the maintainer, who took the defaults of the questions.

## What was missing

Decisions 92 and 103 let `support` answer `BcUnknownTaskException` with `404 Not Found` and
`BcTaskNotOpenException` with `409 Conflict`. The forms of the blueprints answer differently: `404`
for a task which is unknown or not open any more, and `409` for a task which another user claimed.
Two users may open the same form, and only the one who holds the task may send it. `support` had no
exception for that case, so the blueprints wrote their own answers and did not use the exceptions of
`support`.

## The decision

The meaning of the blueprints applies on both platforms:

- `404 Not Found`: there is no open user task of that id. `BcUnknownTaskException` and
  `BcTaskNotOpenException` both get it. For the form the two are the same: it cannot take an answer
  for that task, and the user can do nothing about it.
- `409 Conflict`: the task is open, but another user claimed it. The new
  `BcTaskClaimedByAnotherUserException` in `io.vanillabp.cockpit.support.usertask` says so. Like the
  other two it keeps the id of the workflow and the id of the task. It also keeps the user who
  claimed the task, but only if the workflow module knows it. A module which only asks the cockpit
  whether somebody else holds the task does not know who.

`BcUserTaskExceptionHandler` on Spring Boot and `BcUserTaskExceptionMapper` on Quarkus answer the
three exceptions the same way, with the message as plain text. Everything else decisions 92 and 103
say stays.

The change breaks the answer of a form before 1.0, on purpose. After the release an answer of an API
can no longer change without breaking its users.
