### A REST client of `support` needs no code of its own for plain text, many connections or a start without its framework

#### What was found

Client modules which moved to `ClientsConfigurationBase` still wrote configuration of their own for
three things. An API which answers `text/plain` failed in the JSON decoder, so each such client
replaced the decoder. A load driver which sends many requests at once raised the size of OkHttp's
connection pool by hand, because `Client` had no key for it. And a configuration created with
`new`, as a test creates it, failed at its first call, because the `Optional` field for the JSON
mapper was only set by Spring.

The same three cases were checked for the HTTP service clients and for `RestClients` on Quarkus.
Both read a `String` as text out of the box. Neither had a key for the pool. Apache HttpClient 5,
which Spring Boot picks as soon as it is on the class path, opens five connections to a server and
lets every further request wait. The JDK's `HttpClient` has no limit, and Quarkus allows 50. The
conventions of the HTTP service clients take everything in their constructor and work without an
application context. `RestClients` got its `Config` by field injection, so a builder created with
`new` failed like `ClientsConfigurationBase`.

#### The decision

- The key is `connection-pool-size` on all three, at the prefix of the client or the group, like
  every other key. It has no `vanillabp` in it, and two modules with the same client keep different
  values.
- Each HTTP library reads it in its own way, and the documentation says how. OkHttp keeps that many
  idle connections, five by default, as before. Apache HttpClient 5 opens that many at most, to the
  server and in total. Quarkus opens that many at most, 50 without the key. The JDK's `HttpClient`
  has no limit, so the key changes nothing there and is accepted. Any other HTTP library together
  with the key stops the start, so the key never seems to work while it does nothing.
- `ClientsConfigurationBase` reads an answer into a `String` as text unless its `Content-Type` is
  JSON. A JSON string still loses its quotes, as before, so no client which works today changes.
- `ClientsConfigurationBase` starts with an empty `Optional` for the JSON mapper. Spring replaces
  it. Without Spring, OpenFeign's own decoder reads text.
- `RestClients` reads its configuration through `ConfigProvider` in its constructor and not by
  injection, so `new RestClients()` works outside CDI, inside the running application.
- Apache HttpClient 5 is an optional dependency of `support/spring-boot`, only to set the size of
  its pool. The code which names its classes is a class of its own, which the JVM loads only when
  the application sends with that library.

#### What it costs

A key which changes nothing on the JDK's `HttpClient`. The tests of `support/spring-boot` have
Apache HttpClient 5 on their class path, so they name the JDK's client in their
`application.properties`, and a test which needs another library asks for it.
